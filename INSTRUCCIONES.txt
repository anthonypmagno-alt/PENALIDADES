PORTAL COMPLETO: REVISION DE GUIAS + PENALIDADES

Este paquete integra Penalidades dentro del portal principal. El index.html conserva el inicio de sesión de Revisión de Guías. penalidades.html valida y reutiliza la sesión del portal; no tiene un formulario de login propio.

PUBLICAR EN GITHUB PAGES
1. Descomprime el ZIP.
2. En el repositorio que publicarás con GitHub Pages, carga el CONTENIDO de esta carpeta en la raíz (donde quedará index.html). No subas la carpeta contenedora como un nivel adicional.
3. Conserva juntos index.html, config.js, bridge.js, gestion-v2.html, xlsx-resumen.js, pdv.html, pdv-v2.html, penalidades.html, process-worker.js, pdf-pdv.js y brecha-costos.js.
4. Espera a que GitHub Pages termine de publicar y abre la raíz del portal, por ejemplo https://TU-USUARIO.github.io/TU-REPOSITORIO/. Inicia sesión ahí y entra a la pestaña Penalidades. No abras un index.html independiente de Penalidades.

ACTUALIZACION DE PENALIDADES (09-10-2026)
- El filtro “Brecha (columna E)” permite seleccionar uno o varios valores de la columna E (Brecha) del Excel de penalidades.
- La descarga Excel del detalle incluye GUIA, PENALIDAD, PDV, PORCENTAJE DE EXONERACION, MONTO FINAL (S/), MOTIVO DE DECISION y MONTO INICIAL DE PENALIDAD (S/) como última columna. El archivo descargado termina en _MONTO_INICIAL.xlsx.

- Al actualizar manualmente, reemplaza index.html y penalidades.html. Si subes todo el ZIP, carga su contenido completo en la raíz del repositorio y conserva juntos todos los archivos indicados arriba.

La configuración apunta al proyecto Supabase akultekodxqmmfchxviq. El login usa las cuentas existentes de Supabase Auth. El archivo index.html corresponde al portal completo y debe conservarse para que se muestre ese login.

ACTUALIZACION SQL PARA EL TIMEOUT DEL RESUMEN
En Supabase, dentro del mismo proyecto, ejecuta una vez SUPABASE_SQL/supabase_penalidades_resumen_rapido.sql. Actualiza únicamente la función que entrega el resumen inicial. No borra tablas, liquidaciones, guías ni decisiones. La pantalla carga primero el resumen por periodo/PDV; las guías se solicitan por páginas cuando seleccionas una liquidación.

OTROS SQL (SOLO SI APLICA)
- supabase_penalidades_tasa_firma.sql: ejecutar solo si faltan las columnas Estado/Tasa de firma o si se requiere esa corrección. Es incremental y no reinicia datos.
- supabase_penalidades_autorizacion_perfiles.sql: ejecutar solo si una cuenta válida de administrador/encargado muestra “Cuenta no autorizada” DESPUES de iniciar sesión. No corrige contraseñas.
- supabase_costos_brecha_compartidos.sql: necesario únicamente si aún no se instaló la configuración compartida de costos de brecha.

No ejecutes una instalación desde cero ni scripts de reinicio para esta actualización.

CAMBIO DE CRUCE
En exportación de guías se busca primero coincidencia de guía y PDV; si el PDV no coincide, se usa la coincidencia por guía y la actualización más reciente.


CAMPO MONTO DE LIQUIDACION (10-10-2026)
- El monto se ingresa por cada liquidación en la tabla “Registros guardados”, antes de Penalidad total.
- “Liq. final” se calcula como Monto de liquidación menos Saldo de penalidad. Mientras falte ingresar un monto, el resultado figura como pendiente.
- Los indicadores del detalle muestran el monto de liquidación en azul y la Liq. final en amarillo dorado.
- Para conservar y compartir el monto entre usuarios, ejecuta una sola vez SUPABASE_SQL/supabase_penalidades_monto_liquidacion.sql en el mismo proyecto Supabase. El script es incremental, conserva los registros y decisiones y no requiere reinstalación.

AJUSTE DE TABLA Y MONTO (10-10-2026)
- La tabla de liquidaciones aprovecha el ancho de la pantalla y ajusta los encabezados para mostrar todas sus columnas en escritorio. En pantallas pequeñas conserva el desplazamiento horizontal.
- El campo Monto de liquidación muestra S/ y dos decimales. Al editarlo, se acepta separador decimal con punto o coma; al guardar vuelve a mostrarse con formato monetario.
- No requiere un SQL adicional. El guardado compartido del monto sigue requiriendo la columna instalada por supabase_penalidades_monto_liquidacion.sql.
- El enlace de Penalidades del index.html usa un nuevo identificador para evitar la caché anterior.


ACTUALIZACION MONTO INICIAL DE PENALIDAD (11-10-2026)
- El monto inicial se toma de la penalidad original antes de aplicar el porcentaje de exoneración.
- El monto final permanece como saldo posterior a la exoneración.
- El enlace de Penalidades usa la versión 20261011-monto-inicial-verificado-5 para evitar la caché anterior.
- Este cambio es de exportación y no requiere ejecutar SQL.


ACTUALIZACION GESTION DE GUIAS V2 (12-10-2026)
- El resumen incluye el botón “Solo casos críticos”. Al activarlo, conserva los filtros elegidos y muestra únicamente los PDV cuyo “Total crítico” es mayor que cero; recalcula subtotales y total general para los PDV visibles.
- “Excel resumen” exporta la tabla V2 que se ve en pantalla, con encabezados agrupados, filas por región y área, subtotales, total general y colores. La descarga respeta los filtros aplicados y los grupos que estén desplegados o contraídos.
- El resumen se descarga como un archivo .xlsx real, conservando combinaciones de encabezados, grupos, subtotales, colores y estilos.
- El Excel agrega una columna COMENTARIO a la derecha del cuadro resumen original (después de 💬), con el texto guardado para cada PDV.
- El generador XLSX está incluido localmente como xlsx-resumen.js, así que la descarga no depende de un CDN ni requiere ejecutar SQL.
- El enlace de Gestión de guías V2 incluye el identificador 20261012-resumen-comentarios-xlsx-5 para evitar que el navegador conserve la versión anterior.


RETENCION PARA MEJORA (13-10-2026)
- El porcentaje se aplica al saldo que queda después de la exoneración. El monto retenido se muestra en el detalle, los indicadores y la tabla de liquidaciones.
- La retención es condicional y no se resta de la Liq. final.
- El Excel de detalle conserva sus columnas existentes y termina con RETENCIÓN PARA MEJORA (%) y RETENCIÓN PARA MEJORA (S/).
- Para conservar la retención entre sesiones y compartirla entre usuarios, ejecuta una sola vez SUPABASE_SQL/supabase_penalidades_retencion_mejora.sql en el mismo proyecto Supabase. El cambio agrega una columna a las decisiones existentes y actualiza tres funciones; no elimina registros.
- Publica el contenido completo del ZIP en la raíz del repositorio. El enlace de Penalidades del index usa la versión 20261013-resumen-penalidad-1.


RESUMEN CONTRAIBLE POR PENALIDAD (13-10-2026)
- Cada penalidad muestra una fila agregada. “Expandir todo” abre los motivos y los subtipos; “Contraer por penalidad” vuelve a una fila por penalidad. Los motivos conservan su propio control para abrir o cerrar los subtipos de Brecha o SLA.
- El enlace de Penalidades se actualiza con la versión 20261013-resumen-penalidad-1.
